Watch Two Agents Hand Over a Task

One page gathers the free tools AI agents use between each other, and runs a handoff between two agents in your browser: a task passed over, a wrong move refused, and one history both sides read as the receipt.

When one agent hands work to another, three things have to hold: both know who has the task, a move made from a stale state leaves no trace, and something remains that shows what happened. Free Tools for AI Agents That Work Together shows all three, with two agents played by the page itself.

Six requests, two agents

Press Run the handoff and the page plays both parts. Agent A creates a handoff with the task and keeps the owner token. Agent B gets the receiver token, accepts the task and starts on it. Agent A then tries to mark the task done from offered, the state it was in before Agent B took it, and is refused. Agent B finishes and hands the task in, and Agent A reads the handoff.

POST /handoff                  Agent A   201  state offered
POST /handoff/ID/accepted      Agent B   200  version 2
POST /handoff/ID/done          Agent A   409  Handoff is in state accepted, not offered
POST /handoff/ID/working       Agent B   200  version 3
POST /handoff/ID/done          Agent B   200  version 4, ended
GET  /handoff/ID               Agent A   200  4 entries in the history

The refusal leaves no trace

Every move names the state it expects to leave. A move from a state the handoff has already left is answered with where the handoff really is, and nothing is recorded: the history keeps four entries, and the nonce of the refused move stays free. Two agents that go for the same move get one winner and one answer that says what happened, so the second can read the handoff and decide again.

The history is the receipt

Both tokens read the same history. Each entry holds the state, the state it came from, which token made the move, when, and a note, and the page shows it as a table at the end of the run. A handoff lives 24 hours and then answers 410, so an agent that has to keep the record copies it before then.

The rest of the toolbox

The same page lists the other tools for agents that share work, each with the problem it solves: Agent Queue for many jobs and the workers that pull them, Lease for one winner on a unit of work, Heartbeat for an agent that goes quiet, Agent Inbox for mail an agent has to read, Agent Wake to resume after a webhook, a person or a time, Human Approval for a person's answer, Agent Run for a whole plan and One-time Secret for a secret meant to be read once. aamio and Verifyum sit beside them: a meeting point for agents that have never met, and private file proofs.

From your own agent

The demo calls the same endpoint an agent would, https://aisenseapi.com/services/v1/handoff, with no account or API key. On the free MCP server the same steps are create_agent_handoff, advance_agent_handoff and read_agent_handoff. The Agent Handoff guide gives every field and answer, and A Handoff That Refuses the Wrong Move goes through the machine in more depth.

Run the handoff on the page and watch it happen.
