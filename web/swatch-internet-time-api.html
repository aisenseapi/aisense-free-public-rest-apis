Time - Beats

Swatch Internet Time API

Swatch Internet Time cuts the day into 1000 beats instead of 24 hours, written with a leading @ sign. One beat is 1 minute 26.4 seconds. There are no timezones at all: the whole planet is on Biel Mean Time, so @895 is the same instant in Oslo, Tokyo and Lima.

  • No API key
  • 1000 beats a day
  • No timezones
  • One GET request

Read the beat

GET/swatchinternettime

https://aisenseapi.com/services/v1/swatchinternettime

Read the current beat

curl https://aisenseapi.com/services/v1/swatchinternettime
{"beat":"@895","date":"2026-08-19"}

Both fields describe the same moment. The beat is the internet-time reading, the date is the ordinary calendar date, so you get the novelty value and something a normal system can store without reconstructing one from the other.

Response fields

FieldTypeDescription
beatstringThe current beat, with the leading @ that marks the notation. A day runs from beat 0 to beat 999. It is a string, not a number: strip the @ before doing arithmetic on it.
datestringThe ordinary calendar date as YYYY-MM-DD, returned alongside the beat so a caller has both readings from one request.

How a beat is worked out

  1. Divide the day by 1000

    86400 seconds split into 1000 parts gives 86.4 seconds per beat, which is 1 minute 26.4 seconds. An hour is a little under 42 beats, and 100 beats is 2 hours 24 minutes. There are no hours, minutes or seconds in the notation at all, just the one running count.

  2. Anchor it to Biel

    The count starts at midnight in Biel, Switzerland, which is UTC+1 all year with no daylight saving. Swatch named this Biel Mean Time after the town its headquarters sits in. The anchor is the whole trick: it is a single fixed offset that never shifts.

  3. Throw the timezones away

    Because everyone counts from that one anchor, nobody has a local version of the number. The beat you read is the beat everyone else reads at the same instant, so there is nothing to convert and no offset to carry alongside it.

The formula is small enough to keep in your head: beat = floor(((utc_seconds_since_midnight + 3600) mod 86400) / 86.4). This endpoint exists so a browser page, a shell script or an embedded display can show the value without implementing that, and so every client in a system reads it off the same clock.

Where it goes wrong

A beat is 86.4 seconds wide, so this is a coarse clock. Two events a minute apart usually land on the same beat, and you cannot order them afterwards. Anything that needs second or sub-second resolution belongs in the Unix Timestamp API instead.

The count wraps from 999 back to 0, and it does so at midnight in Biel, which is 23:00 UTC. That catches people twice. Values are not monotonic across a day boundary, so beats alone will not sort a log correctly - keep the date field with them. And the rollover is an hour before UTC midnight, so a fresh @000 does not mean a fresh UTC date.

Nothing consumes this format. No operating system parses it, no protocol accepts it, no database has a column type for it. Treat it as a display value or as a shared human-readable label, and store a real timestamp underneath whenever the value has to survive, be compared, or be handed to another system.

Where it came from

Swatch, the Swiss watchmaker, introduced Internet Time in 1998 and sold watches that displayed beats. The pitch fitted the moment: the web had just made it normal to talk to someone twelve timezones away, and the company argued that a network-native clock should not be tied to a place. Announcing a new unit of time is also, of course, very good marketing for a watch company.

It never displaced ordinary time. No standards body adopted it, no operating system shipped it, and the watches stopped being the point fairly quickly. What it did was survive as a curiosity. It was used for an online game's server clock, giving players in different countries one number to arrange things by, and it still turns up in demo scenes, status pages and hobby projects that want a clock that looks like it belongs to the network rather than to a country.

That is the honest description of what this endpoint returns: a genuinely timezone-free notation with a real design idea behind it, kept alive because it is fun, not because anything depends on it.

Common uses

Novelty clock display

Drive a dashboard tile, a terminal prompt or a small e-ink panel with a clock that reads @895 instead of 21:28 and needs no date library to render.

Timezone-free coordination

Stamp messages in a global chat room or a game lobby with a beat so players in six countries read one number and nobody has to work out whose evening it is.

Teaching time representations

Use it next to a Unix timestamp and an ISO 8601 string to show students that a moment can be counted from different anchors in different units, and that the anchor is the part that matters.

Retro-styled interfaces

Fit a late-nineties or cyberpunk visual theme with a clock format that actually dates from that era, rather than faking one.

Privacy and limits

The endpoint takes no input, so there is nothing about the caller in the request to store. The response depends only on the server clock.

The value changes every 86.4 seconds, so do not put it behind a cache or a CDN rule that would serve a stale beat. The service-wide limit is 5000 requests per IP per 24 hours, which is far more than a display clock needs if you poll it once a beat.
