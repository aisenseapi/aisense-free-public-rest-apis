Transform - Text

Slugify API

Text in, URL slug out. Scandinavian letters and common Latin diacritics are transliterated by a fixed table, so the same input gives the same slug on every machine, every time.

  • No API key
  • Deterministic
  • Handles æ ø å
  • One POST request

Make a slug

POST/slugify

https://aisenseapi.com/services/v1/slugify

Slugify a title

curl -X POST https://aisenseapi.com/services/v1/slugify \
  -H "Content-Type: application/json" \
  -d '{"data": "Blåbærsyltetøy på Ås!"}'
{ "slug": "blabaersyltetoy-pa-as" }

German sharp s and umlauts follow the same table: Große Übung becomes grosse-ubung.

Response fields

FieldTypeDescription
slugstringLowercase a-z, 0-9 and single hyphens. Never empty: input that leaves nothing after filtering returns HTTP 400 instead.

Why a fixed table

  1. Transliterate

    æ becomes ae, ø becomes o, å becomes a, ß becomes ss, and accented Latin letters lose their accents. The table is fixed in the source rather than borrowed from the host's locale, which is what makes the output identical across machines.

  2. Filter

    Everything outside a-z and 0-9 collapses into single hyphens, trimmed at both ends.

  3. Refuse emptiness

    Input with no sluggable characters returns HTTP 400 rather than an empty string a caller would build a URL out of.

Common uses

CMS paths

Turn article titles into stable URL paths.

File naming

Derive safe filenames from user-supplied titles.

Agent output

Let a language model hand over a title and receive a path-safe identifier.

Cross-system keys

Generate the same key from the same name in every service that needs it.

Privacy and limits

The text travels in the POST body, not the URL, so it does not appear in request paths.

The service-wide limit is 5000 requests per IP per 24 hours.
