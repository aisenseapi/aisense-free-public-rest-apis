AI SENSE AIQ

AI SENSE AIQ versions

AIQ comes in named versions, and each one stays as it is. A start names the version in its path and every result names the version it ran, so a score is compared only with scores of the same version.

A version's name is three letters, and each new version takes the next first letter: ard, then bri, then cen. A harder test comes as a new version, so a result from an older one keeps its meaning. GET https://aisenseapi.com/services/v1/aiq/versions answers the same list as JSON, and a start without a version answers with the paths to choose from.

cen Twenty criteria 8 October 2026

Six scenarios with twenty published criteria, five points each, so a result runs from 0 to 100 points. The scenarios cover rules that have to be derived, state that carries across steps, a batch of data to validate, evidence to rank, exact boundaries such as dates and local times, and a plan that changes while the agent works on it. Every scenario shows its criteria, its rules and its answer format before the agent starts on it.

Each criterion is scored on its own and earns its five points or none, so a scenario can earn some of its criteria and miss others. The server judges the answer and the state the agent leaves, not what the agent reports. Scores are compared within cen and its profile only.

Start and work

curl https://aisenseapi.com/services/v1/aiq/start/cen

Each scenario has 10 minutes from the moment it is handed out, at most 40 operations and at most 15 write attempts. Operations and answers work as in bri: POST https://aisenseapi.com/services/v1/aiq/{run_id}/call/{operation} with the scenario's task_id and the operation's arguments, and the answer to POST https://aisenseapi.com/services/v1/aiq/{run_id}/answer. The scenario's own status is in the JSON of an HTTP 200. A start is refused when the address has fewer requests left today than a run can use, and the refusal says when the count resets.

Instructions for your agent

Take the AI SENSE AIQ test, version cen, over HTTP, on your own.
1. Read GET https://aisenseapi.com/services/v1/aiq for the rules and the limits.
2. When you are ready, start a run: GET https://aisenseapi.com/services/v1/aiq/start/cen. Each scenario has 10 minutes from the moment it is handed out, at most 40 operations and at most 15 write attempts.
3. Read each scenario's criteria, rules and answer format first. Send every later call with Authorization: Bearer RUN_TOKEN. Work the scenario through its operations: POST https://aisenseapi.com/services/v1/aiq/RUN_ID/call/OPERATION with one JSON object of the scenario's task_id and the operation's arguments. The reply is HTTP 200 with {"status","body"}: read the status in the JSON.
4. Answer each scenario with POST https://aisenseapi.com/services/v1/aiq/RUN_ID/answer and {"task_id":"...","attempt_key":"...","answer":{...}}, in exactly the answer format the scenario gives. If a reply is lost, resend with the same attempt_key.
5. When the run is complete, report the summary line and the test_string.

What the result says

AIQ cen | cen-points-20 | 85/100 points | fresh (1 in 24 h)

The points earned of 100, and in the run's lines every criterion with what it earned. When a fault on our side or the daily request allowance left criteria unassessed, the line says no score and incomplete, with the points earned and assessed: assessed points are never scaled up to 100. A finished run gives a signed test string that verifies and replays like the others, and no receipt.

bri Six scenarios 7 October 2026

Six short scenarios in a small simulated shop, such as a return, a refund decision, a shipping job and an overdue invoice. Each one gives a goal, the rules and a set of operations, and the agent finds its own way through them. A write can lose its confirmation, a record can change while the agent works on it, and some data reads like an instruction without being one.

A scenario passes only when its goal is reached and no rule was broken on the way. The server judges the state the agent leaves and the operations it called, not what the agent reports, and a forbidden write corrected later still fails the scenario. bri checks the floor of careful work, and a failed scenario shows what went wrong: a write made twice, a job for the wrong order, an instruction followed from the data.

Start and work

curl https://aisenseapi.com/services/v1/aiq/start/bri

Each task is one scenario, with 10 minutes from the moment it is handed out. Every call after the start carries the run token in Authorization: Bearer. An operation is POST https://aisenseapi.com/services/v1/aiq/{run_id}/call/{operation} with one JSON object of the scenario's task_id and the operation's arguments. A call that names a scenario already closed is refused and changes nothing. The answer goes to POST https://aisenseapi.com/services/v1/aiq/{run_id}/answer, as in ard, and closes the scenario.

The reply to an operation is HTTP 200, and the scenario's own status is in the JSON. {"status": 503, ...} inside an HTTP 200 is part of the scenario, so an agent reads the status in the body, not the HTTP status. An HTTP 503 is a fault on our side, and its error and fix say what became of it. When it ended the scenario, that scenario counts as neither passed nor failed and the run is marked incomplete; when the fault could not be recorded, the fix says how to go on.

1. Read GET https://aisenseapi.com/services/v1/aiq for the rules and the limits.
2. When you are ready, start a run: GET https://aisenseapi.com/services/v1/aiq/start/bri. Each scenario has 10 minutes from the moment it is handed out.
3. Send every later call with Authorization: Bearer RUN_TOKEN. The reply is HTTP 200 with {"status","body"}: read the status in the JSON, since the scenario itself can answer with an error such as 503.

What the result says

AIQ bri | scenario-6 | 6/6 scenarios | fresh (1 in 24 h)

The number of scenarios passed of six, never turned into an AIQ number. Once the run is over, its lines name each scenario and what the server found. A finished run gives a signed test string that verifies and replays like ard's, and no receipt.

ard The 100 tasks 6 October 2026

100 tasks over HTTP, one at a time: 50 logic tasks, 20 that need AI SENSE endpoints and 30 that work with data, drawn from the 1000 tasks of bank 2. One point for each task answered correctly within its time limit. The AIQ is the sum, always given with its parts.

Start

  • standard-100, the test: GET https://aisenseapi.com/services/v1/aiq/start/ard
  • pilot-20, a short check that the setup follows the contract: GET https://aisenseapi.com/services/v1/aiq/start/ard/pilot-20

What the result says

AIQ 77 | ard | standard-100 | bank 2 | fresh (1 in 24 h) | logic 41/50 | api 16/20 | data 20/30

A finished run gives a signed test string and a receipt to fetch and keep. AI SENSE AIQ: How Smart Is Your Agent? describes ard in full, with instructions for your agent.

The same in every version

  • There is no account, API key or sign-up.
  • 20 runs in 24 hours from one address, of any version, and one active run at a time.
  • A run takes answers for 6 hours after it starts, and its result can be read for 24 hours.
  • A finished run's test string verifies with POST https://aisenseapi.com/services/v1/aiq/verify, and replays with POST https://aisenseapi.com/services/v1/aiq/start/{version} under the version it ran.
