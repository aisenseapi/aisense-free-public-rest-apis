Time - WorldTimeAPI paths

Free WorldTimeAPI Alternative

WorldTimeAPI was the clock behind a great many ESP32 sketches, Arduino projects, games and scripts, and it no longer answers: on 3 October 2026 every connection to worldtimeapi.org, over HTTP and HTTPS, was reset. Its paths and its fifteen fields answer here, free and without a key. Change the host, keep the code.

  • No API key
  • Same paths
  • Same fifteen fields
  • JSON or .txt

Time in a zone

GET/api/timezone/Europe/Oslo

https://aisenseapi.com/api/timezone/Europe/Oslo

One change is not optional: this host answers HTTPS only. A sketch that fetched http://worldtimeapi.org over a plain WiFiClient has to use https:// and a WiFiClientSecure, shown below.

The paths

PathAnswer
/api/timezoneEvery current zone name, as a JSON list
/api/timezone/{area}The zones of one area, such as Europe or America
/api/timezone/{area}/{location}[/{region}]The fifteen fields for that zone, such as America/Argentina/Buenos_Aires
/api/ipThe fifteen fields where your address is
/api/ip/{address}The fifteen fields where that IPv4 or IPv6 address is

Add .txt to any of them for one key: value per line, with a null left empty. Zone names match in any case and old names are accepted. The same paths also answer under /services/v1/worldtime/ for anyone who keeps every call under one prefix.

The fifteen fields

FieldTypeMeaning
abbreviationstringThe local abbreviation, such as CEST, EDT or IST, or a numeric one such as -03 where the database has no letters.
client_ipstringThe address the request came from, also on /api/ip/{address}.
datetimestringLocal date and time, ISO 8601 with microseconds and the offset.
day_of_weekinteger0 for Sunday to 6 for Saturday.
day_of_yearintegerLocal day of the year, starting at 1.
dstbooleanWhether summer time is in force.
dst_fromstring or nullWhen the current summer time period began, in UTC. null when dst is false.
dst_offsetintegerSeconds summer time adds now: 3600 almost everywhere, 1800 on Lord Howe Island, 0 outside summer time.
dst_untilstring or nullWhen the current summer time period ends, in UTC. null when dst is false.
raw_offsetintegerThe standard offset from UTC in seconds, without summer time.
timezonestringThe zone name in its usual case. Old names such as Europe/Kiev are accepted.
unixtimeintegerSeconds since 1970-01-01 UTC.
utc_datetimestringThe same moment in UTC, ending in +00:00.
utc_offsetstringThe offset in force now, as +HH:MM, summer time included.
week_numberintegerThe ISO 8601 week.

The names, types and meanings are WorldTimeAPI's, and so is the order, alphabetical. Slashes in zone names are not escaped, so code that looks for Europe/Oslo in the body as text still finds it.

On an ESP32

The usual sketch called http.begin("http://worldtimeapi.org/api/timezone/Europe/Oslo"). Over HTTPS the call takes a secure client. The shortest version skips certificate checks, which is acceptable for reading a clock and nothing more:

#include <WiFiClientSecure.h>
#include <HTTPClient.h>

WiFiClientSecure client;
client.setInsecure();          // or client.setCACert(...) to check the certificate

HTTPClient http;
http.begin(client, "https://aisenseapi.com/api/timezone/Europe/Oslo");
int code = http.GET();
String body = http.getString();
http.end();

Parsing does not change: the fields are the ones the sketch already reads. For an ESP8266 the class is BearSSL::WiFiClientSecure with the same setInsecure().

Errors, in WorldTimeAPI's words

CaseStatusBody
Unknown zone404{"error":"unknown location Europe/Pari","fix":"..."}, or Error: unknown location Europe/Pari as text
Address with no zone in the database404{"error":"unknown location for ip ...","fix":"..."}
Malformed address400{"error":"malformed ip","fix":"..."}
Over 5000 calls from one address in a day429With Retry-After until midnight Oslo time

The error text is the one WorldTimeAPI sent; the fix beside it is ours and says what to send instead.

Where the answers come from

Zone names and their rules come from the time zone database built into the server's PHP, which is updated with PHP releases. The zone of an address comes from GeoLite2-City, read locally and cached for an hour per address, so a device that asks every minute costs one lookup an hour. Nothing you send is stored; the request log keeps the status and how long the answer took.

If you only need a zone you already know, /datetime/Europe/Oslo answers a shorter object with the offset in force and whether summer time is on.

Privacy and limits

The address in /api/ip/{address} is looked up and not kept. Looking up someone else's address tells you roughly where on the map it is registered, which is all a time zone needs and all the database knows.

Every path shares the service-wide ceiling of 5000 requests per IP address per day. No key, no account and no sign-up. The whole catalogue is on Free public REST APIs.
