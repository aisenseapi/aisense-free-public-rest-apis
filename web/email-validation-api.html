Web utility - Validation

Email Validation API

Check an address in two layers: syntax first, then whether the domain can receive mail at all. One POST request, no account, no API key, and no SMTP probe against anyone's mailbox.

  • No API key
  • Syntax + DNS
  • No third party
  • No SMTP probe

Validate an address

POST/email_validate

https://aisenseapi.com/services/v1/email_validate

Validate an address

curl -X POST https://aisenseapi.com/services/v1/email_validate \
  -H "Content-Type: application/json" \
  -d '{"data": "test@gmail.com"}'
{
  "email": "test@gmail.com",
  "valid_syntax": true,
  "domain": "gmail.com",
  "has_mx": true,
  "mx_hosts": ["gmail-smtp-in.l.google.com", "alt1.gmail-smtp-in.l.google.com"],
  "has_address_record": true
}

An address that fails is a result, not an error: valid_syntax comes back false with HTTP 200. Only a request with no input at all returns HTTP 400.

Response fields

FieldTypeDescription
emailstringThe address as received, trimmed.
valid_syntaxbooleanWhether the address parses as an email address.
domainstring or nullThe domain part, lowercased. Null when syntax fails.
has_mxbooleanWhether the domain publishes MX records.
mx_hostsarrayUp to five MX hosts, lowest preference first.
has_address_recordbooleanWhether the domain resolves to A or AAAA. RFC 5321 allows delivery through this fallback, so a missing MX alone does not prove an address dead.

What it checks, and what it deliberately does not

  1. Syntax

    The address is parsed. Internationalized domains are not converted to punycode and report valid_syntax false.

  2. DNS

    MX records are read through the host resolver only. Nothing is sent to any third party.

  3. Nothing further

    No SMTP conversation is opened, so the API never confirms whether a mailbox exists. A public endpoint that probes mailboxes is an abuse tool, and this one is not.

Common uses

Form validation

Reject typo domains before an application accepts a signup.

Agent input checking

Verify an address a language model extracted before it is used anywhere.

List hygiene

Flag entries whose domains no longer publish mail records.

Support tooling

Show whether a customer-supplied address can receive mail at all.

Privacy and limits

The address travels in the POST body, not the URL, so it does not appear in request paths. DNS questions about the domain go through this server's resolver as any lookup must.

The service-wide limit is 5000 requests per IP per 24 hours.
