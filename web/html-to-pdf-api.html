HTML to PDF API

Send a string of HTML, get back a URL to a rendered PDF. The response is not the file: the service renders your markup, stores the result, and hands you the address to fetch it from. Collecting the document is a second request.

  • No API key
  • Two step flow
  • A4 pages
  • Link expires in 24 hours

Render a PDF

POST/html2pdf

https://aisenseapi.com/services/v1/html2pdf

Render, then download

The first call renders the document and returns JSON. No PDF bytes come back on this request.

curl -X POST https://aisenseapi.com/services/v1/html2pdf \
  -H "Content-Type: application/json" \
  -d '{"data":"<h1>Invoice 4817</h1><p>Paid</p>"}'
{"storage_id":"1c896e41-d5b7-4017-b888-8381d7866088","storage_url":"https://aisenseapi.com/services/v1/storage/1c896e41-d5b7-4017-b888-8381d7866088","expire_timestamp":1787257796}

The identifier above is from one real call and has long since expired - yours will differ on every request. The second call fetches storage_url. It answers with Content-Type: application/pdf and the file itself, roughly 12 KB for the two line document above.

STORAGE_ID="the storage_id from the response above"
curl -o invoice.pdf "https://aisenseapi.com/services/v1/storage/$STORAGE_ID"

Response fields

FieldTypeDescription
storage_idstringUUID of the stored file. Useful as a key if you are tracking the render in your own system.
storage_urlstringAbsolute URL of the PDF. A plain GET returns the file with Content-Type: application/pdf. No header, token or cookie is required.
expire_timestampintegerUnix timestamp in seconds, 24 hours after the render. Once that moment passes the file is gone and the URL stops serving it.

Why two calls

  1. Render

    POST the markup as the data field of a JSON body. The renderer lays it out and writes a PDF into temporary storage. You get JSON describing where it went, which keeps the response small and lets you queue the download separately from the render.

  2. Collect

    GET the storage_url whenever you are ready, as many times as you like inside the window. This is the same storage layer the Temporary Storage API exposes, so the file behaves like any other stored object.

  3. Keep it yourself

    The URL is for collection, not hosting. Anything that has to survive past the day it was made must be downloaded and written somewhere you control. Do not put the storage URL in an invoice email or a database row you expect to still work next week.

What the renderer does with your markup

The engine is a document typesetter, not a browser screenshot. Send self contained markup: there is one data field and no place to attach stylesheets, page options or assets alongside it. A bare fragment works, and so does a complete document with a <style> block in the head.

Three things are worth knowing before you build a template around it.

  • Pages come out A4 portrait, 595 by 842 points. There is no parameter for letter size, landscape or margins.
  • The output embeds its own serif face. A font-family declaration did not change it in testing, so structural markup carries the design: headings, bold, paragraphs and tables come through, exact typography does not.
  • An empty or missing data field is not an error. The call returns HTTP 200 and a valid PDF containing a blank page, so a template bug shows up as an empty document rather than a failed request. Check that your markup is non empty before you post it.

Page size, orientation and margins

An optional options object controls the page setup. It is accepted alongside html, which is an alias for data - both name the markup to render.

curl -X POST https://aisenseapi.com/services/v1/html2pdf \n  -H "Content-Type: application/json" \n  -d '{"html":"<h1>Quarterly report</h1>","options":{"page-size":"A5","orientation":"Landscape","margin-top":"20mm"}}'
OptionAccepted valuesEffect
page-sizeA3, A4, A5, Letter, Legal, TabloidPaper size. A4 gives a 595 by 842 point page, A5 landscape 595 by 420, Letter 612 by 792.
orientationPortrait, LandscapePage orientation.
margin-top, margin-bottom, margin-left, margin-rightUp to three digits with an optional mm, cm or in suffix, for example 20mmPage margin on that edge.

Every value is checked against the list above before it reaches the renderer, and anything unrecognised is ignored rather than passed through. That is deliberate: the renderer is a command line tool, and a whitelist is the only safe way to let a caller influence its arguments.

Common uses

Invoices and receipts

Fill an HTML template with line items and totals, render it, and file the PDF against the order the moment it is paid.

Printable reports

Take the table a dashboard already renders and turn it into a fixed page a colleague can print, sign or archive.

Email attachments

Convert generated markup into a PDF before sending, so the recipient gets a document rather than a styled message that reflows in their client.

Documents an agent produces

Let a language model write the markup for a summary or a form and hand back a file a human can open, file and keep.

Privacy and limits

The PDF URL is unauthenticated and holds whatever you rendered. Anyone with the link can read the document until it expires. Do not send personal, financial or confidential material through a public service.

The markup travels in the POST body rather than the URL, so it does not land in request paths or logs of intermediate proxies. The rendered file still sits in shared temporary storage for 24 hours.

The service-wide limit is 5000 requests per IP per 24 hours. Each render and each download counts, so a render plus a collect is two requests.
